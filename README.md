##  Project Overview

**NeoVerse** is a console-based C++ AI City Survival System designed to demonstrate advanced programming concepts including dynamic data structures, Standard Template Library (STL) containers and algorithms, algorithm efficiency, object-oriented programming (OOP), real-world problem solving, and file persistence.

The system simulates the management of city data, events, emergency alerts, city components, reports, and persistent system information.

### Core Areas
* **AI Engineer Authentication & Access Control**
* **City Data Management** (Vectors & Linked Lists)
* **Event Processing System** (Queues & Stacks)
* **Object-Oriented City Architecture** (Polymorphism & Inheritance)
* **STL Algorithms & Performance Optimization**
* **System Reports & Analytics**
* **File Handling & Persistence** (Binary, Text, & CSV I/O)

## 🏛️ System Functionality

### 1. AI Engineer Authentication
* Stores engineer data (ID, username, encrypted password, clearance level) using an STL `vector`.
* **Complexity Consideration:** 
  * Linear search performs at **O(n)** time complexity.
  * Binary search can achieve **O(log n)** efficiency if data is appropriately sorted.

### 2. City Data Management
* **Vectors:** Used for daily sensor readings, population metrics, energy usage, traffic density, and alerts. Provides constant-time indexed access at **O(1)**.
* **Linked Lists (`std::list`):** Used for historical city logs to allow dynamic growth without contiguous memory requirements. Traversing takes **O(n)**, while insertions/removals at known positions take **O(1)**.

### 3. Event Processing System
* **Queue (`std::queue` - FIFO):** Handles standard city events (traffic accidents, power failures, network overloads, weather alerts) in the order they arrive. Operations (`push()`, `pop()`) run at **O(1)**.
* **Stack (`std::stack` - LIFO):** Manages emergency overrides, ensuring the most recent critical override is addressed first. Operations (`push()`, `pop()`) run at **O(1)**.

### 4. Object-Oriented City Architecture
The system uses a robust class inheritance hierarchy originating from a base `CityComponent`:

```text
                     CityComponent (Base)
                           |
    ------------------------------------------------
    |                    |             |            |
PowerSystem     TransportSystem   HealthSystem  SecuritySystem
```
* **Encapsulation:** Class fields are kept private and accessed via public methods.
* **Inheritance:** Specialized systems inherit core attributes and virtual behaviors.
* **Polymorphism:** Base class pointers (`CityComponent*`) invoke overridden virtual functions like `processEvent()` dynamically.

### 5. STL Algorithms & Performance
The project leverages standard STL algorithms for efficiency:
* `sort()`: Arranges sensor readings in ascending order -- **O(n log n)**
* `find()`: Locates specific events in a collection -- **O(n)**
* `min_element()` / `max_element()`: Finds boundary sensor values -- **O(n)**
* `count_if()`: Counts critical alerts matching specific criteria -- **O(n)**

### 6. System Reports & Analytics
Generates insights including total events processed, most common emergency types, average response times, and system load summaries using STL iterators, algorithms (`min_element`, `max_element`, `accumulate`), and frequency tracking.

### 7. File Handling & Persistence
Utilizes C++ file streams (`std::ofstream`, `std::ifstream`, and binary mode `ios::binary`) to save and load system states across multiple files:
* `engineers.dat`: Binary storage for engineer credentials.
* `events.dat` & `city_logs.dat`: System event and history persistence.
* `config.txt`: Readable system configuration properties (e.g., `CITY_NAME=NeoVerse`).
* `city_logs.csv`: Structured historical log exports.
