NeoVerse: AI City Survival System

Programming 622 -- C++ Assignment

1. Project Overview

NeoVerse is a console-based C++ AI City Survival System developed to
demonstrate dynamic data structures, STL containers, STL algorithms,
algorithm efficiency, object-oriented programming, real-world problem
solving, and file persistence.

The system simulates the management of city data, events, emergency
alerts, city components, reports, and stored system information.

The project is divided into the following main areas:

AI Engineer Authentication & Access Control

City Data Management

Event Processing System

Object-Oriented City Architecture

STL Algorithms & Performance Optimisation

System Reports & Analytics

File Handling & Persistence

6. System Functionality

6.1 AI Engineer Authentication

Engineers must authenticate before accessing the city system.

The Engineer class stores:

Engineer ID

Username

Encrypted password

Clearance level

Engineers are stored using an STL vector.

The <algorithm> library is used when searching for valid credentials.

Login search complexity

A linear search has:

O(n)

time complexity in the worst case.

A binary search can achieve:

O(log n)

but requires the data to be appropriately sorted and maintained.

The implementation uses the approach required by the assignment and
demonstrates the associated Big-O consideration.

7. City Data Management

The city data section uses dynamic STL containers.

Vector

A vector is used for daily sensor readings.

Example data includes:

Sensor readings

Population-related values

Energy usage

Traffic density

Alerts

A vector provides constant-time indexed access:

O(1)

for direct element access.

Linked List

A list is used for historical city logs.

The linked list allows the historical log collection to grow dynamically
without requiring contiguous memory.

Insertion/removal at a known list position can be:

O(1)

once the appropriate iterator is available.

Traversal is:

O(n)

because each element must be visited.

8. Event Processing System

The system handles different city events, including:

Traffic accident

Power failure

Network overload

Weather alert

Queue -- FIFO

The event queue uses:

queue<Event>

A queue follows:

First In, First Out (FIFO)

This means events are processed in the same order in which they arrive.

Typical queue operations such as push() and pop() are:

O(1)

Stack -- LIFO

Emergency overrides use:

stack<EmergencyEvent>

A stack follows:

Last In, First Out (LIFO)

This allows the most recent emergency override to be handled first.

Typical stack operations such as push() and pop() are:

O(1)

10. STL Algorithms

The project uses the required STL algorithms:

Algorithm         Purpose                       Time Complexity

sort()          Sort sensor readings          O(n log n)
find()          Search for a specific event   O(n)
min_element()   Find lowest sensor value      O(n)
max_element()   Find highest sensor value     O(n)
count_if()      Count critical alerts         O(n)

Why these algorithms are used

sort()

Used to arrange sensor readings in ascending order.

Average/worst-case complexity: O(n log n)

find()

Used to locate a specific event in a collection.

Worst-case complexity: O(n)

min_element()

Used to find the lowest sensor reading.

Complexity: O(n)

max_element()

Used to find the highest sensor reading.

Complexity: O(n)

count_if()

Used to count alerts that satisfy a critical-alert condition.

Complexity: O(n)
